## 00 一页速览

**一句话概括：** 这是一个「最小可运行的 GPT 式语言模型」——输入两个 token（如 `A is`），输出词表上 17 个词的概率分布，取最大者作为预测的下一个词（`boy`）。训练就是不断微调 345 个浮点数，让 22 条训练语料中正确答案的概率尽量接近 1。

**它与 ChatGPT 在结构上同源**：词嵌入 → 位置编码 → 因果自注意力 → 前馈网络 → 输出头 → softmax → 交叉熵损失。差别在于规模、层数、以及用「有限差分数值梯度」代替了反向传播。

### 整体数据流

```
token ids  →  E + PE  →  Q K V  →  S = QKᵀ/√d  →  + 因果掩码  →  A = softmax  →  O = AV
(2,) int      (2, 5)    (2,5)×3    (2, 2)           (2, 2)         (2, 2)          (2, 5)

→  FFN  →  取末位  →  输出头  →  softmax  →  交叉熵  →  数值梯度 + Adam
(2,5)      h=(5,)    logits(17,)  prob(17,)  loss      更新 345 个参数
```

### 训练在做什么

1. 对当前 `theta` 的**每一个分量**分别 ±1e-5，重算全部 22 条语料的总损失；
2. 用中心差分得到 345 维梯度 `g`；
3. Adam 做动量与自适应缩放，得到 `update`；
4. `theta -= update`，打印新旧 Loss 与每条语料的预测；
5. 重复，直到所有语料都预测正确且概率 > 0.9（日志中 Step 51 触发）。

### 关键量级

| 项目 | 数值 |
|------|------|
| 可训练参数 | 345（源码版本 295） |
| 训练语料 | 22 条 / 17 词 |
| 每步前向次数 | 2 × 345 × 22 = 15,180 |
| 51 步累计前向 | ≈ 77 万次 |
| 实测复现耗时 | 31.9 秒 |
| 初始 / 最终 Loss | 2.8635 / 0.0047 |

## 01 这个模型到底在学什么

日志第 6 行给出词表，第 9–31 行给出 22 条训练语料。把语料整理成规则，可以立刻看出任务的真实结构：

| 主语组 | + is（系动词） | + can（情态动词） | 样本数 |
|--------|----------------|-------------------|--------|
| A, B, C, D, E | **boy**（5 条） | **strong**（5 条） | 10 |
| M, N, Q, P, Z | **girl**（5 条） | **soft**（5 条） | 10 |
| X | **boy**（重复 2 条） | 语料中**不存在** | 2 |

所以模型要学的其实是一张 **2 × 2 的组合查表**：`（主语类别 ∈ {组1, 组2}）×（谓词 ∈ {is, can}）→ 4 个标签词之一`。这一点非常重要——它意味着我们后面看到的所有数学运算，本质上都在实现一个「先判断主语属于哪一类、再判断谓词是哪一个、最后组合出答案」的函数。

> **为什么这仍算「语言模型」？** 因为它做的是标准自回归语言建模的一步：`P(下一个词 | 上文)`。真实 GPT 做的事完全一样，只是上文更长、词表几万、层数几十、并且把预测出的词再拼回输入循环生成。这个 demo 刻意把问题压缩到「两个词 → 一个词」，好让每一步的中间张量都能打印出来肉眼检查。

**两个可从语料中读出的细节：**

- `X is → boy` 在日志中出现**两次**（第 21、22 条）。在 `np.mean(losses)` 下，重复样本等价于把该样本的梯度权重加倍——所以 X 会被更用力地拉向 boy 组。这个「重复」在后面的泛化实验里会起作用。
- 4 个标签词 `girl / boy / strong / soft` **只作为答案出现，从不作为输入出现**。这个看似无关的事实，会在第 11 章引出一个非常有意思的现象。

## 02 配置与维度：每个超参数是什么意思

| 符号 | 源码值 | 日志实际值 | 含义与作用 |
|------|--------|------------|------------|
| `D` | 5 | 5 | **嵌入维度**。每个词用一个 5 维向量表示；也是整个网络残差通路上的「通道宽度」。 |
| `DK` | 5 | 5 | **Q / K / V 的投影维度**。单头注意力中一般取 DK = D；多头时每个头取 D / h。 |
| `D_FF` | 5 | **10** | **FFN 隐藏层宽度**。真实 Transformer 常取 4D。日志为 10，所以 `W1 (5,10)`、`W2 (10,5)` 才真正构成「升维 → 降维」。 |
| `MAX_LEN` | 4 | 4 | 预生成位置编码表的最大长度。本例所有样本长度都是 2，只用 `PE[:2]`。 |
| `NUM_LAYERS` | 1 | 1 | 注释写「单层 Transformer」，但**该变量在代码中从未被使用**，层数实际是硬编码在 `forward` 里的一次。 |
| `VOCAB_SIZE` | 由数据决定 | 17 | 词表大小，决定 `E` 与 `WU` 的行数、以及 logits 的维数。 |
| `SCALE` | √DK ≈ 2.236 | √5 | 注意力打分的缩放因子，防止点积数值过大把 softmax 推进饱和区。 |
| `LAMBDA` | 0.001 | 0.001 | L2 正则系数，见第 6、8、11 章——它在这里产生了一个反直觉的副作用。 |
| `STEPS / LR` | 200 / 0.05 | 实际 51 步 | 最大迭代数与 Adam 学习率。0.05 对这种小模型偏大，是 Loss 曲线出现来回震荡的主因。 |
| `eps` | 1e-5 | 1e-5 | 数值梯度的扰动步长（注意与 Adam 里的 1e-8 是两回事）。 |
| `NPARAM` | 295 | **345** | 参数总数 = 各矩阵元素数之和。 |

### 345 是怎么算出来的

```
NPARAM = 17×5 + 5×5 + 5×5 + 5×5 + 5×10 + 10×5 + 17×5
       = 85 + 25 + 25 + 25 + 50 + 50 + 85 = 345
```

对应源码版本（`D_FF = 5`）则是 `85 + 25×3 + 25 + 25 + 85 = 295`。日志第 33 行「共 345 个参数」正是这一配置。

> **关于 `np.set_printoptions(precision=4, suppress=True, linewidth=120)`**：只影响打印，不影响计算。`precision=4` 保留 4 位小数，`suppress=True` 不用科学计数法显示极小值，`linewidth=120` 控制折行宽度。日志中所有矩阵看起来整齐，就是这条语句的功劳。

## 03 数据层：从 `tr_data` 到 `ids`

源码第 47–78 行的 `load_data()` 做了四件事：

```python
with open(DATA_FILE, 'r', encoding='utf-8') as f:
    content = f.read()
local_vars = {}
exec(content, {}, local_vars)               # ① 把数据文件当 Python 代码执行
VOCAB = local_vars['VOCAB']                 # ② 取出词表
TRAINING_DATA_RAW = local_vars['TRAINING_DATA']
ID = {w: i for i, w in enumerate(VOCAB)}    # ③ 词 → 整数 id
TRAINING_DATA = []
for input_words, target_word in TRAINING_DATA_RAW:
    input_ids = [ID[w] for w in input_words]
    target_id = ID[target_word]
    TRAINING_DATA.append((input_ids, target_id, input_words, target_word))  # ④ 四元组
```

| 变量 | 类型 / Shape | 含义 |
|------|-------------|------|
| `VOCAB` | list[str]，长度 17 | 词表。**下标即 token id**：`VOCAB[0]='A'`，`VOCAB[15]='is'`，`VOCAB[16]='can'`。 |
| `ID` | dict[str, int] | 反向映射，用于把用户输入的词转成 id。推理时 `input_ids = [ID[w] for w in input_words]`。 |
| `TRAINING_DATA_RAW` | list[(list[str], str)] | 原始字符串形式的 `(输入词列表, 目标词)`。 |
| `TRAINING_DATA` | list[4 元组] | `(input_ids, target_id, input_words, target_word)`。前两项供计算，后两项仅供打印日志。 |
| `input_ids / ids` | list[int]，长度 2 | 例如 `A is` → `[0, 15]`（日志第 168 行可核对）。 |
| `target / target_id` | int（标量） | 正确答案在词表中的下标，例如 `boy` → 12。 |

> **工程提示：** `exec()` 会把数据文件里的任意 Python 代码都执行一遍，教学场景无所谓，真实项目应改用 `json` / `csv` / `ast.literal_eval`。另外 `load_data()` 是在模块顶层调用的（第 81 行），所以**只要 import 这个模块就会立刻读文件**，缺少 `tr_data` 时直接 `sys.exit(1)`。

## 04 参数体系：`theta` 与 7 个矩阵

### 为什么把所有参数压成一个一维向量

源码第 90–119 行定义了 `SHAPES / KEYS / SIZES` 和 `pack / unpack`：

```python
def unpack(theta):
    d, i = {}, 0
    for k, n in zip(KEYS, SIZES):
        d[k] = theta[i:i + n].reshape(SHAPES[k])
        i += n
    return d
```

`theta` 是一个长度 345 的一维 `float64` 向量，是**模型唯一的「真身」**；7 个矩阵只是它的 7 段**视图（view）**。这样设计完全是为了服务第 7 章的数值梯度：有限差分需要对「第 i 个参数」做 `theta[i] += eps`，一维向量最容易按索引扰动。`reshape` 返回的是视图而非拷贝，因此 `unpack` 出来的矩阵与 `theta` 共享内存（本例只读不改，无副作用）。

### theta 的分段结构

```
|←──── E (0–84) ────→|← Wq →|← Wk →|← Wv →|←── W1 (160–209) ──→|←── W2 (210–259) ──→|←──── WU (260–344) ────→|
```

- **输入侧**：E（词嵌入）
- **注意力**：Wq, Wk, Wv
- **FFN**：W1, W2
- **输出侧**：WU（解嵌入）

### 7 个矩阵的完整定义

| 符号 | Shape | 个数 | 数学作用 | 直观解释 |
|------|-------|------|----------|----------|
| **E** | (17, 5) | 85 | `X₀ = E[ids]` | **词嵌入表（Embedding）**。第 i 行是第 i 个词的 5 维向量。整个模型对「词义」的全部知识都在这张表里；训练会把它塑造成按类别聚类的结构（见第 11 章）。 |
| **Wq** | (5, 5) | 25 | `Q = X·Wq` | **查询投影**。把每个位置的向量变换成「我在找什么信息」。 |
| **Wk** | (5, 5) | 25 | `K = X·Wk` | **键投影**。把每个位置变换成「我能被怎样检索」。`Q·Kᵀ` 的点积就是匹配分数。 |
| **Wv** | (5, 5) | 25 | `V = X·Wv` | **值投影**。真正被加权求和、传递给下一层的内容。 |
| **W1** | (5, 10) | 50 | `H = ReLU(O·W1)` | **FFN 升维层**。把 5 维映射到 10 维，配合 ReLU 提供非线性，是模型实现「组合规则」的主要算力所在。 |
| **W2** | (10, 5) | 50 | `O' = H·W2` | **FFN 降维层**。映射回 5 维，使形状与输入一致（真实模型里靠残差连接相加）。 |
| **WU** | (17, 5) | 85 | `logits = h·WUᵀ` | **输出头 / 解嵌入矩阵（unembedding）**。第 j 行是第 j 个词的「输出向量」；`h` 与它的点积越大，模型越认为该词是答案。与 `E` **不共享权重**（未做 weight tying）。 |

**初始化**（源码第 279–280 行）：`rng = np.random.default_rng(42)`，`theta = rng.normal(0.0, 0.3, NPARAM)`。即 345 个数独立采样自 `N(0, 0.3²)`。固定随机种子 42 保证每次运行完全一致——这也是我能够逐位复现日志的前提。日志第 35–111 行打印的就是这 345 个数被 `unpack` 后的 7 个矩阵。

> **偏置项去哪了？** 所有线性层都**没有 bias**，这是刻意的简化。真实 Transformer 的 QKV / FFN / LM head 通常也常省略 bias（现代 LLM 多用无偏置线性层 + RMSNorm），所以这一点与工业实践并不矛盾。

## 05 前向传播：7 步逐一拆解

入口是 `forward(theta, ids, target, need_cache, verbose)`（源码第 142 行）。以下按日志里 `verbose=True` 打印的 Step 编号讲解，并统一采用样本 `A is → boy`（`ids=[0,15]`，`seq_len=2`，日志第 166–207 行）。所有 shape 均以 `D=5, D_FF=10, VOCAB_SIZE=17` 为准。

### Step 1 · `X = E[ids] + PE[:seq_len]` → 形状 (2, 5)

`E[list(ids)]` 是 NumPy 的**花式索引**：取出第 0 行和第 15 行，堆叠成 (2,5)。再加上同样 (2,5) 的位置编码前两行，得到 `X`——序列中每个位置的一个 5 维向量，同时携带「是什么词」和「在第几个位置」两种信息。

#### 位置编码 PE 是怎么算出来的

```python
def positional_encoding(max_len, d):
    P = np.zeros((max_len, d))
    for pos in range(max_len):
        for i in range(0, d, 2):          # i = 0, 2, 4
            denom = 10000 ** (i / d)
            P[pos, i]     = np.sin(pos / denom)
            if i + 1 < d:
                P[pos, i+1] = np.cos(pos / denom)
    return P
```

```
PE[pos, 2j]   = sin(pos / 10000^(2j/D))
PE[pos, 2j+1] = cos(pos / 10000^(2j/D))
```

不同维度对应不同波长（从 2π 到 10000·2π 量级），形成一组「多频率时钟」，让模型能区分绝对与相对位置。本例 D=5 是奇数，`i=4` 时 `i+1=5` 不 < 5，故**最后一维只写了 sin 而没写 cos**，是简化实现的边界情况。实际生成的 `PE (4,5)` 为：

| pos | dim0 sin(pos) | dim1 cos(pos) | dim2 sin(pos/39.81) | dim3 cos(pos/39.81) | dim4 sin(pos/1584.9) |
|-----|---------------|---------------|---------------------|---------------------|----------------------|
| 0 | 0.0000 | 1.0000 | 0.0000 | 1.0000 | 0.0000 |
| 1 | 0.8415 | 0.5403 | 0.0251 | 0.9997 | 0.0006 |
| 2 | 0.9093 | −0.4161 | 0.0502 | 0.9987 | 0.0013 |
| 3 | 0.1411 | −0.9900 | 0.0753 | 0.9972 | 0.0019 |

日志第 169–171 行的 `X`（注意这是 **Step 1 更新之后**的权重算出来的，所以不等于初始 E + PE）：

```
[[ 0.1414  0.638   0.2751  1.2322 -0.5353]     # 位置 0：词 A
 [ 0.9986  0.4621  0.0227  1.2374 -0.0422]]    # 位置 1：词 is
```

PE 在源码第 84 行只生成一次、全局复用，是**固定不可训练**的正弦编码（区别于 GPT 早期版本的可学习位置嵌入，也区别于现代 LLM 的 RoPE）。

### Step 2 · 因果掩码 `causal_mask` → 形状 (2, 2)

```python
causal_mask = np.triu(np.ones((seq_len, seq_len)) * -np.inf, k=1)
# 结果：
[[  0., -inf],
 [  0.,   0.]]
```

`np.triu(..., k=1)` 保留**主对角线右上方**的元素，其余置 0。于是上三角（代表「未来位置」）被填成 −∞，softmax 后变成精确的概率 0。这就是 **causal / 单向注意力**：位置 *i* 只能看到 0…*i*，不能偷看后面的词——语言模型不作弊的保证。

> 对本例 `seq_len=2` 而言，掩码意味着**位置 0 只能看自己，位置 1 能看 0 和 1**。因此注意力矩阵第一行**恒等于 [1, 0]**，没有任何可学习性；整个训练中真正有信息的注意力权重只有第二行的两个数字。这是 2-token 序列 + 因果掩码的天然局限，也解释了后面 Wq/Wk 的梯度为什么一直偏小。

### Step 3 · `Q = X·Wq`、`K = X·Wk`、`V = X·Wv` → 各 (2, 5)

三次独立的线性投影，`(2,5) @ (5,5) → (2,5)`。同一份 `X` 被投影到三个不同「角色空间」：

- **Q（Query，查询）**：当前位置发出的「我想找什么样的信息」；
- **K（Key，键）**：每个位置挂出的「索引标签」，供 Q 做匹配；
- **V（Value，值）**：匹配成功后真正被取走、加权平均的内容。

一个常用的类比：Q 是搜索词，K 是文档标题，V 是文档正文。`Q·Kᵀ` 得到相关性分数，再用这个分数对 V 做加权求和。注意这里 `X` 已经被加上了 PE，所以 Q/K/V 天然含有位置信息（不同于 RoPE 在打分阶段才注入位置）。

### Step 4 · `S = Q @ K.T / SCALE + causal_mask` → (2, 2)

`Q @ K.T` 是 `(2,5) @ (5,2) → (2,2)` 的两两内积矩阵：`S[i,j]` 表示「第 i 个位置对第 j 个位置的关注原始分数」。加上掩码后，右上角的未来位置变成 −∞。日志第 172–174 行：

```
[[0.2332   -inf]      # 位置 0：只能看自己，分数 0.2332
 [0.1965 0.1818]]     # 位置 1：看位置 0 得 0.1965，看自己得 0.1818
```

**为什么除以 √DK？** 若 Q、K 各分量近似方差 1 的独立随机变量，其点积方差约为 DK，DK 越大分数绝对值越大，softmax 越接近 one-hot，梯度 `A(1−A)` 越接近 0 → 训练卡死。除以 `√DK = √5 ≈ 2.236` 把方差拉回 1，这是《Attention Is All You Need》里的标准做法（*scaled dot-product attention* 名称的由来）。

### Step 5 · `A = softmax(S, axis=1)` → (2, 2) `注意力权重矩阵`

```python
def softmax(z, axis=-1):
    e = np.exp(z - z.max(axis=axis, keepdims=True))
    return e / e.sum(axis=axis, keepdims=True)
```

`z - z.max()` 是**数值稳定技巧**：减去最大值不改变 softmax 结果（分子分母同除 `e^max`），但能保证 `exp` 的参数 ≤ 0，避免溢出。对 −∞ 也安全：有限最大值减去后仍是 −∞，`exp(−∞)=0`。

`axis=1` 表示**按行**归一化：每一个查询位置 *i*，对它能看到的所有键位置 *j* 形成一个概率分布，`A[i,:].sum() == 1`。日志第 175–177 行：

```
[[1.     0.    ]      # 位置 0：被掩码逼成 [1, 0]
 [0.5037 0.4963]]     # 位置 1：几乎平均地看两个位置
```

### Step 6 · `O = A @ V` → (2, 5)

`(2,2) @ (2,5) → (2,5)`。`O[i] = Σⱼ A[i,j] · V[j]`，即「按注意力权重对全部可见位置的值向量做加权平均」。因为 `A[1] ≈ [0.5, 0.5]`，位置 1 的输出基本是 `V[0]` 与 `V[1]` 的平均——这正是把两个词的信息融合成一个上下文向量的地方。

> 注意变量命名：`O` 在第 170 行是注意力输出，在第 177 行又被 **FFN 的输出覆盖**（同名复用）。所以日志 `[Step 5] FFN` 打印的 `O` 已经不是 `A @ V` 了。阅读代码时这是一个容易混淆的点。

### Step 7 · FFN：`hidden = ReLU(O @ W1)`，`O = hidden @ W2` → (2, 5)

```python
hidden = O @ p["W1"]        # (2,5) @ (5,10) → (2,10)  升维
hidden = np.maximum(0, hidden)  # ReLU：逐元素 max(0, x)
O = hidden @ p["W2"]        # (2,10) @ (10,5) → (2,5)  降维
```

这是 **position-wise 前馈网络**：对序列中每个位置**独立地**施加同一个两层 MLP，位置之间在此处不交换信息（信息交换只发生在注意力层）。ReLU 提供非线性——没有它，`W1·W2` 会坍缩成一个等价的线性变换，整个网络就退化成线性分类器，无法表达「主语组 × 谓词」这种组合逻辑。

源码注释写「FFN 第一层：升维」，但**只有在 `D_FF > D` 时才成立**：日志版本 5→10 确实升维；当前源文件 `D_FF = 5` 是 5→5，并没有升维。真实模型一般取 `D_FF = 4D`（并常用 GELU / SwiGLU 代替 ReLU）。

### Step 8–10 · 取末位、输出头、概率与损失

#### Step 6（日志编号）· `h = O[-1]` → (5,)

只取**最后一个位置**的向量作为整个上文的汇总表示。这是因果语言模型的标准做法：最后一个位置是唯一「看过全部上文」的位置，用它来预测下一个词最合理。日志第 184–185 行：`h = [0.2379, 0.1016, 0.2300, −0.1642, −0.1680]`。

> **一个细节：** 位置 0 的 FFN 输出 `O[0]` 被直接丢弃，它对 loss *没有直接贡献*；但它对应的 `V[0]` 会通过位置 1 的注意力权重 `A[1,0]` 影响 `O[1]`，所以位置 0 的计算并非完全白做。真实实现（如带 KV cache 的推理）会避免这类冗余。

#### Step 7（日志编号）· `logits = h @ WU.T` → (17,)

`(5,) @ (5,17) → (17,)`。`logits[j] = h · WU[j]`，即汇总向量与第 j 个词的输出向量做点积。数值越大代表模型越倾向该词。这一步叫 **LM head / 解嵌入**。日志第 186–188 行给出 17 个 logit，Step 1 时都接近 0（约 −0.27 ~ +0.21），所以概率近似均匀。

#### 输出 · `prob = softmax(logits)` → (17,)

把 logits 转成和为 1 的概率分布。日志第 189–206 行逐词打印；`boy: 0.0592`，恰接近 `1/17 = 0.0588`，说明训练刚开始时模型基本在瞎猜。

#### 损失 · `loss = -np.log(prob[target] + 1e-12)`

只取正确答案对应的那个概率取负对数。`+1e-12` 防止 `log(0)` 得到 −∞。日志第 207 行：`−log(0.0592) = 2.8262`。

#### `cache` 字典

`{"X", "h", "logits", "prob", "params"}` 保存中间结果。**在真实反向传播里，这些正是需要缓存以计算梯量的激活值**；但本 demo 用的是数值梯度，所以 `cache` 实际上只被 `predict_next()` 用来读 `prob`。参数 `need_cache` 传入后**从未被读取**，无论 True/False 都会构造并返回 cache。

## 06 损失函数与 L2 正则

源码第 207–226 行是三层结构，务必分清：

| 函数 | 返回值 | 用途 |
|------|--------|------|
| `forward(...)` | 单条语料的 `loss` + cache | 纯交叉熵，不含正则 |
| `compute_loss_single(theta, ids, target)` | 标量 loss | 丢弃 cache，供批量计算 |
| `compute_loss_all(theta)` | `(avg_loss, losses[22])` | **日志里打印的「平均Loss」就是它**：`mean(22 条交叉熵)` |
| `total_loss(theta)` | `avg_loss + LAMBDA·(θᵀθ)` | **真正被用来求梯度与更新的目标函数** |

```
J(θ) = (1/N) Σₙ −log p_θ(yₙ | xₙ) + λ‖θ‖²，λ = 0.001，N = 22
```

> **常见误读：** 日志中所有 `平均Loss`、`loss=...` 都来自 `compute_loss_all`，**不包含正则项**；而参数更新依据的梯度来自 `total_loss`，包含正则项。所以「日志 loss 已经是 0.0000，但训练仍在改动参数」并不矛盾——正则项还在产生梯度。

### 为什么初始 Loss ≈ 2.86

初始权重很小（σ=0.3），前向传播各层输出的量级都很小，logits 接近 0，softmax 近似均匀分布 `1/17 ≈ 0.0588`。于是 `−ln(1/17) = ln 17 ≈ 2.8332`。日志第 114 行是 **2.8635**，略高于理论值，是因为随机初始的 logits 不完全为 0，带来少量额外损失；第 116–137 行各样本的 `P` 都在 0.05~0.06 之间，正好印证这一点。

### 交叉熵的梯度（本 demo 没用，但必须知道）

softmax + 交叉熵组合有一个极其漂亮的解析梯度：

```
∂L/∂logitsⱼ = probⱼ − 1[j = target]
```

即「预测概率减去正确答案的 one-hot」。它意味着**词表里每一个词的 logits 都会收到梯度**：正确词被向上推，其余 16 个词被向下压。这一点是理解第 11 章「为什么 WU 的 17 行全都变了，而 E 只有 13 行变了」的钥匙。

## 07 数值梯度：用最笨的办法求导数

```python
def numerical_grad(theta, eps=1e-5):
    g = np.empty_like(theta)
    for i in range(len(theta)):
        a = theta.copy(); a[i] += eps
        b = theta.copy(); b[i] -= eps
        g[i] = (total_loss(a) - total_loss(b)) / (2 * eps)
    return g
```

这是**中心差分（central difference）**，即导数的定义式近似：`∂J/∂θᵢ ≈ [J(θᵢ+ε) − J(θᵢ−ε)] / 2ε`，截断误差 O(ε²)，比前向差分 O(ε) 更准。ε 不能太大（截断误差）也不能太小（浮点舍入误差被 2ε 放大），1e-5 是 float64 下常用的折中值。

### 成本量化

| 环节 | 次数 |
|------|------|
| 每个参数需要 2 次 `total_loss` | 2 |
| 每次 `total_loss` 遍历 22 条语料的前向 | 22 |
| 每步梯度 | 345 × 2 × 22 = 15,180 次前向 |
| 51 步累计 | ≈ 774,180 次前向 |
| 实测总耗时（Python 3.11 + NumPy） | 31.9 秒 |

真实框架用**反向传播 / autograd**：一次前向 + 一次反向即可拿到全部梯度，成本约为 2~3 次前向，与参数量**近似无关**。这里相当于慢了 4~5 个数量级。教学上这很划算——不需要推导任何链式法则，就能直观看到「梯度 = 每个参数对损失的边际影响」；工程上则完全不可扩展，这是 PyTorch / JAX 存在的根本理由。

> 日志第 209–216 行打印的「梯度详情」是 `g_p = unpack(g)` 后**每个矩阵梯度的 L2 范数**，用来观察哪一部分参数在主导学习。例如 Step 1：`WU=0.1593`、`W1=0.1381` 最大，而 `Wq=0.0182`、`Wk=0.0092` 最小。

## 08 Adam：从梯度到参数更新

```python
m = 0.9 * m + 0.1 * g          # β₁ = 0.9   一阶动量（梯度的指数滑动平均）
v = 0.999 * v + 0.001 * g * g  # β₂ = 0.999 二阶动量（梯度平方的滑动平均）
mh = m / (1 - 0.9 ** step)     # 偏差修正 bias correction
vh = v / (1 - 0.999 ** step)
update = LR * mh / (np.sqrt(vh) + 1e-8)
theta -= update
```

| 变量 | Shape | 含义 |
|------|-------|------|
| `g` | (345,) | 当前步数值梯度 |
| `m` | (345,) | 一阶矩估计，平滑梯度方向、抑制震荡 |
| `v` | (345,) | 二阶矩估计，逐参数自适应调整步长：梯度大的方向走小步，梯度小的方向走大步 |
| `mh / vh` | (345,) | 修正后的估计。因为 m、v 初始化为 0，早期会严重偏小，除以 `1−βᵗ` 消除该偏置 |
| `update` | (345,) | 本步实际参数改变量；`1e-8` 防止除以 0 |
| `old_theta` | (345,) | 更新前的拷贝，仅用于在同一份参数上打印「旧 Loss → 新 Loss」对比 |

> **关键推导：Adam 的第一步更新量与梯度大小无关。**
>
> 当 `m=v=0`、`step=1` 时：`m = 0.1g`，`v = 0.001g²`；偏差修正后 `mh = 0.1g/0.1 = g`，`vh = 0.001g²/0.001 = g²`；于是 `mh / √vh = g / |g| = sign(g) ⇒ update = LR · sign(g) = ±0.05`
>
> 这就是 Adam 的**尺度不变性**：把梯度整体乘以任何常数，更新量几乎不变。它让优化对损失函数的量级不敏感，是 Adam 好用的核心原因；但在本 demo 里，它会把一个原本「微乎其微」的 L2 正则梯度也放大成每步 0.05 的固定步长——第 11 章的奇异现象正来源于此。

另外，本实现用的是 **Adam 而非 AdamW**：L2 正则被加进 loss 里（等价于带缩放的权重衰减），而现代 LLM 普遍使用解耦权重衰减的 AdamW。此处 `LR=0.05` 固定不衰减、也没有 warmup，因此 Loss 曲线会反复小幅回升。

| Step 20 | [0.5130, 0.4870] | 日志 789 行 |
| Step 40 | [0.5324, 0.4676] | 日志 1321 行 |

从头到尾都接近均匀的 0.5 / 0.5，`Wq`、`Wk` 的梯度范数在早期也是 7 个矩阵中最小的（Step 20：`Wq=0.0025`、`Wk=0.0022`，而 `WU=0.5646`）。结论：**在这个只有 2 个 token、且位置 0 被掩码钉死的任务里，注意力机制基本沦为一次「近似平均池化」**，真正承担分类的是 `Wv + FFN + WU` 这条通路。想让 attention 真正起作用，需要更长的序列、更依赖词序的任务，以及多步 / 多头结构。这恰恰说明：*把 Transformer 的骨架跑通*和*让注意力学到可解释的模式*是两件不同的事。

## 11 两个从日志里挖出来的精彩发现

### 发现一：词嵌入矩阵 E 自动形成了语义聚类

日志第 1631–1648 行是训练后的 `E (17,5)`。把它按行分组看，结构一目了然：

| 词 | 训练后的 E 行（5 维） | 解读 |
|----|----------------------|------|
| A / B / C / D / E | `[−0.55, 0.35, −0.88, 0.89, 0.48]` 等 | 5 行彼此**高度相似** → 被压成「boy 组」 |
| X | `[−0.38, 0.66, −0.79, 0.75, 0.26]` | 明显更靠近 A–E 组，因为 `X is → boy`（且重复两次） |
| M / N / Q / P / Z | `[1.00, 0.28, 0.54, −0.36, −0.98]` 等 | 另一簇，第 0 维显著为正、第 3/4 维为负 → 「girl 组」 |
| is / can | `[−0.47, 0.85, −0.91, 0.98, 0.47]` / `[0.81, −1.03, 0.32, −0.30, −0.97]` | 两者**差异极大**，因为谓词是决定答案的第二个维度 |
| girl/boy/strong/soft | ≈ `[0.01, −0.00, −0.02, −0.01, 0.01]` … | **几乎全零**！见发现二 |

没有人显式告诉模型「A、B、C、D、E 是一类」。它只是反复被梯度要求「这几个词在相同语境下必须给出相同答案」，于是**自动把它们调整到嵌入空间中彼此相邻的位置**。这就是分布式表示（distributed representation）最直观的一次演示：语义相似性被编码成向量几何上的邻近性。真实大模型的 word2vec 效应、类比推理能力，原理与此同源，只是维度和语料规模放大了千万倍。

### 发现二：4 个从未作为输入的词，其 E 行被 Adam + L2 「匀速清零」

`girl / boy / strong / soft` 只作为 `target` 出现，**从不出现在 `ids` 里**，因此 `E` 的第 11–14 行**收不到来自交叉熵的任何梯度**；它们唯一的梯度来源是 L2 正则项 `∂(λ‖θ‖²)/∂θ = 2λθ`——一个非常小的量。

按常理，这么小的梯度应该几乎不改变这些行。但第 8 章的推导告诉我们：Adam 的更新量近似 `LR·sign(g)`，**与梯度幅值无关**。于是 `sign(2λθ) = sign(θ)`，每一步都稳定地把这些行朝 0 推 `0.05`；约 4~9 步归零后，在 0 附近被数值梯度的微小噪声扰动，最终稳定在 0.01 量级。

我用复现实验实测了训练后 `E` 每一行的 L2 范数：

| 类别 | E 行范数范围 | 具体数值 |
|------|-------------|----------|
| 作为输入出现的 13 个词 | **1.35 ~ 1.72** | A 1.4862 · X 1.3546 · is 1.7185 · can 1.6899 · … |
| 从未作为输入的 4 个词 | **0.012 ~ 0.030** | girl 0.0303 · boy 0.0123 · strong 0.0176 · soft 0.0251 |

相差约 **100 倍**，与日志中那几行接近零的数字完全吻合。作为对照，`WU` 的 17 行范数都在 0.70~1.61 之间、没有任何一行归零——因为 softmax 的梯度 `prob − onehot` 对**全部 17 个 logits** 都非零，所以输出头的每一行都持续被训练，包括这 4 个词。

**这个现象的教学价值：**

- 它把「嵌入表 E」与「输出头 WU」两个角色彻底区分开了：E 按输入 token *稀疏查表*，WU 对全部词 *稠密打分*。
- 它说明「正则项 + 自适应优化器」的组合可能产生非直觉的副作用，且副作用与梯度幅值无关。
- 它顺带解释了工业界常见的 **weight tying**（把 E 与 WU 绑成同一个矩阵）的一个动机：共享后每个词无论作为输入还是输出都能收到梯度，不会出现「半张表被遗忘」的情况，同时还能省下 `V×D` 个参数。

## 12 推理模式与一次「组合泛化」

主程序第 413–419 行用**命令行参数有无**区分两种模式：无参数 → `train_mode()`；有参数 → `inference_mode(sys.argv[1:])`。例如：

```bash
python3 transformer_demo.py              # 训练并保存 ./model_weights.npy
python3 transformer_demo.py A is         # 加载权重，预测下一个词
```

`inference_mode` 先校验所有输入词都在 `ID` 中（否则列出词表并退出），再 `load_weights()`、打印 7 个矩阵，最后调用 `predict_next()`。`predict_next` 里 `forward(..., target=0, verbose=True)` 传的 `target=0` 只是为了让函数能算出 loss（推理时这个 loss 没有意义，被 `_` 丢弃），真正用的是 `cache['prob'].argmax()`，并用 `█` 字符画出概率条。

### 实测推理结果（基于复现出的权重）

| 输入 | 预测 | 概率 | 是否在训练集中出现 |
|------|------|------|-------------------|
| `A is` | **boy** | 1.0000 | 是 |
| `A can` | **strong** | 1.0000 | 是 |
| `M is` | **girl** | 0.9907 | 是 |
| `M can` | **soft** | 0.9931 | 是 |
| `X is` | **boy** | 1.0000 | 是（且重复两次） |
| `X can` | **strong** | 1.0000 | **否 —— 组合泛化** |

最后一行最有意思：训练语料里**从来没有 `X can`**，模型却给出了 `strong`。原因是 `X` 的嵌入被两条 `X is → boy` 样本拉进了 A–E 组（见发现一），而 `can` 的嵌入在全部 10 条 `… can → strong/soft` 样本中承担了「切换到能力形容词」的作用；两个因素在 FFN 里被组合，模型把这个未见过的组合**插值**到了 `strong`。这是组合泛化（compositional generalization）的一个微型实例，也正是「分布式表示」相对「死记硬背查表」的优势所在。

> **但也别高估它：** 这个 demo **没有自回归生成循环**——预测出的词不会拼回输入继续生成，所以它只能做「一步预测」，不能写文章。补上 `while len(ids) < MAX_LEN: ids.append(argmax(prob))` 并加上 EOS，才算一个完整的生成式 LM（注意 `MAX_LEN=4` 与固定 PE 表会限制长度）。

## 15 思考题与动手实验

### 思考题

**Q1.** 为什么初始平均损失是 2.8635，而不是 0？

<details>
<summary>查看要点</summary>

随机小权重 → logits ≈ 0 → 17 类近似均匀 → `−ln(1/17) = ln 17 ≈ 2.8332`；多出的 0.03 来自 logits 的随机波动。

</details>

**Q2.** 如果把 `causal_mask` 删掉，会发生什么？

<details>
<summary>查看要点</summary>

对 `seq_len=2` 且只取 `O[-1]` 的场景，位置 1 原本就允许看全部位置，掩码只影响位置 0；而位置 0 的输出被丢弃，所以**这个 demo 里几乎看不出差别**。这正是「掩码看起来没用」的原因，也是理解因果注意力时最容易产生的错觉——一旦序列变长或对所有位置都算 loss，掩码立刻变得至关重要。

</details>

**Q3.** 为什么 `Wq`/`Wk` 的梯度范数长期最小、A 一直接近 0.5？

<details>
<summary>查看要点</summary>

2-token 序列里位置 0 的注意力被掩码钉死为 [1,0]，只剩位置 1 一行有可学习自由度；且任务不依赖精细的词序关系，Attention 退化为近似平均池化，主要判别能力由 V + FFN + WU 承担。

</details>

**Q4.** 日志打印的 loss 已经到 0.0000，为什么参数还在变？

<details>
<summary>查看要点</summary>

打印的是不含正则的 `compute_loss_all`；更新用的是含 `λ‖θ‖²` 的 `total_loss`。正则项仍有梯度，配合 Adam 尺度不变性，仍会每步推动参数约 0.05。

</details>

**Q5.** 把 `LAMBDA` 设为 0，训练后 `E` 的 girl/boy/strong/soft 四行会怎样？

<details>
<summary>查看要点</summary>

它们的交叉熵梯度恒为 0，只剩数值梯度的舍入噪声。Adam 会把这点噪声放大成 `±0.05` 的随机游走，因此四行会保持在初始值附近随机漂移，而**不会**像现在这样整齐地趋近 0。做一次这个实验，能最直观地验证第 11 章的机制。

</details>

**Q6.** 如果做 `weight tying`（令 `WU = E`），参数量变成多少？

<details>
<summary>查看要点</summary>

省掉一个 `(17,5)` 的矩阵，从 345 降到 260。同时那 4 个输出词会通过 WU 一侧收到梯度，其 E 行不再被遗忘。

</details>

**Q7.** 为什么 `X can → strong`，尽管训练集中没有这条？

<details>
<summary>查看要点</summary>

X 的嵌入被归到 A–E 组，`can` 在 10 条样本中稳定地把输出切到「能力形容词」；两者组合被 FFN 插值到 `strong`。这是分布式表示带来的组合泛化，而非记忆。

</details>

**Q8.** 把 `STEPS` 改成 200、去掉提前停止，最终会发生什么？

<details>
<summary>查看要点</summary>

Loss 会长期贴近 0 并小幅震荡，`h` 的模长继续增大（softmax 越来越尖锐），参数范数与正则项缓慢上升，可能出现数值饱和。这是没有早停 / 学习率衰减 / 权重衰减时常见的「过自信」现象。

</details>

### 建议动手做的 4 个实验

1. **对齐配置：** 把 `D_FF` 改成 10，放入配套的 `tr_data`，重跑训练，核对是否能得到 51 步 / 0.0047。
2. **去掉位置编码：** 把 `X = p["E"][list(ids)] + PE[:seq_len]` 改成只取 `E[ids]`，观察 `A is` 与 `is A` 是否变得无法区分，体会 PE 的作用。
3. **改正则：** 分别设 `LAMBDA = 0` 和 `LAMBDA = 0.1`，训练后打印 `E` 各行范数，验证第 11 章结论。
4. **换优化器：** 把 Adam 换成 `theta -= 0.1 * g`（朴素 SGD），对比收敛速度与曲线平滑度，理解自适应步长与偏差修正的价值。
